# Private archive codec: local preparation only

`PrivateArchive` is an independent Java11 streaming backend. It is not registered
in the host runner or exposed by Activity. It neither exports provider destinations
nor imports, promotes, prunes or changes live state. This slice does not establish
M1 completion, a successful backup receipt, or device acceptance.

Run actual production codec tests with the installed JDK17:

```sh
PATH=/workspace/.command-library-env/jdk-17.0.16+8/bin:$PATH bash verification/private_archive/run.sh all
```

`codec` selects framing/fault/resource checks; `memory` selects the constrained
heap and total-length checks. The runner compiles the actual production class
with `javac --release 11`, without Android doubles or external dependencies.
Generated classes/temporary synthetic archives stay in ignored `verification/build`.
Small corrupt fixtures use arrays only in tests; large fixtures never materialize
a document or archive in memory.

## Version1 wire contract

All integers use big-endian encoding. There is no compression, ZIP, filename,
filesystem path, free-form string, extraction operation or optional extension.
Entry IDs must be RFC4122 variant UUID v4, generated by the source. The decoder
checks this shape and rejects repeats across every category; it cannot prove
which generator originally created an ID.

| Segment | Bytes |
| --- | --- |
| Header | ASCII `MDESKBACKUP` followed by `0D 0A 1A 0A` (15 bytes), version `uint32=1` |
| Entry | marker `uint8=1`, type `uint8`, UUID `uint128` (two longs), length `uint64`, payload SHA-256 (32 bytes), exact payload |
| Terminal | marker `uint8=0`, entry count `uint32`, preceding stream length `uint64`, preceding stream SHA-256 (32 bytes) |

The terminal length/digest cover the header and every complete entry, including
entry metadata and payload, and exclude the terminal itself. `ArchiveSummary`
contains the count plus the length/digest of the **entire stream**, including
terminal. A terminal is required even for zero entries. Signed Java `long` values
with the wire sign bit set are rejected because they exceed every allowed bound.
A version, type, marker, invalid UUID, duplicate, truncated field/payload, bad
payload/terminal hash, inconsistent length/count or trailing byte fails explicitly.
Concatenated archives fail the trailing-byte check.

| Type ID | Private category | Entry byte cap |
| --- | --- | --- |
| 1 | Snapshot | 8,388,608 + 32,768 |
| 2 | Preparation | 65,536 |
| 3 | Completion | 65,536 |
| 4 | Checkpoint | 65,536 |
| 5 | Identity | 65,536 |
| 6 | Session tab | 8,388,608 + 32,768 |
| 7 | Recovery | 8,388,608 + 32,768 |
| 8 | Preferences | 65,536 |

The complete accepted stream is capped at 1,073,741,824 bytes, including terminal,
with at most 65,536 entries. A separate 16,777,216-byte metadata index budget
charges a conservative 384 bytes for each UUID/frame/bookkeeping slot before
payload work or a sink callback. This bounds the UUID uniqueness index without
retaining records or payloads, and currently binds first at 43,690 entries.
The transfer buffer is 65,536 bytes; write hashes and rechecks one entry at a time
through two fresh streams. There is no archive-sized array or seek requirement.

The wire has no strings to decode. The planned 4,096 UTF-8-byte string limit and
strict UTF-8/range/reference validation belong to future typed payload decoders,
not this framing layer. Session tab and recovery entries are reserved for future
typed raw document content plus bounded metadata: later decoders must enforce
the exact 8,388,608-byte document cap and individual metadata bounds. This framing
cap does not promise acceptance of opaque legacy session/recovery JSON. Similarly,
a framing-valid preferences payload is not an allowlisted preferences import.
SHA-256 supplies integrity checking, not authentication, encryption or a claim
that payload semantics or the protection graph are valid.

## Stream ownership and staging contract

`ArchiveSource.next()` enumerates immutable `SourceEntry` handles until null;
each opener returns a fresh, repeatable, bounded stream at byte zero. IDs/type/
length are validated before opening it. `write` owns and closes both per-entry
streams, including failures. It does not close source enumeration or the caller's
archive output, and does not flush it. Changed length/hash or any source/open/
read/close/output error prevents a returned summary. Partial output remains the
caller's responsibility.

`EntrySink.begin(Entry)` returns a private staging output. Every callback is
**provisional**. After non-null begin succeeds, `finish(entry,output,payloadVerified)`
runs once, including on payload failures. The default finish does nothing; callers
can override it to flush/close each stage promptly without retaining open outputs
until the archive ends. The codec itself never closes or flushes staging outputs
or the caller's archive input. A finish exception prevents a summary; if there is
also a read/hash exception, the finish exception is suppressed on the first one.
`payloadVerified=true` means only the entry hash/length matched; a subsequent
terminal/trailing-byte/other-entry error still invalidates the whole archive.

Only a successfully returned `read` summary establishes whole-stream framing and
hash verification. It is not authority to adopt data. Future import must independently
validate typed fields, strict UTF-8, preferences allowlists, references and graph,
namespace-remap IDs, stage durably and explicitly activate selected state. There
are no grants, document writes or adoption actions here. Failed staging cleanup
and preservation are caller policy.

Likewise a returned `write` summary is not an export receipt: output flush/close,
provider write/readback verification, source pins, destination eligibility and
durable intent are the separate planned `PrivateExport` lifecycle. The codec
cannot observe an error occurring after its caller flushes/closes an output.

## Evidence and limits

Tests cover all eight categories and exact BOM/CRLF/Unicode bytes, true zero-record
archives, every truncation byte in a small fixture, independently forged framing,
valid metadata changes covered by terminal digest, invalid UUIDs, unknown magic/
version/type/marker, overflow/oversize declarations, duplicate IDs, payload/terminal
corruption, trailing/concatenated archives and the exact index-budget boundary.
Fault streams exercise non-seekable short reads, zero bulk reads, owned-source
close failures on both passes, enumeration/open/read/output failures, changed
sources, sink begin/write/finish errors and suppressed cleanup failures. Each
output-failure position leaves an archive that cannot verify. A missing or bad
terminal can follow completed staging callbacks and still prevents a summary.

The memory target uses `-Xmx128m`, retains 32MiB of filled arrays throughout,
roundtrips 20 generated near-limit snapshot entries (168,427,380 payload bytes)
through a temporary file, and checks every payload byte with streaming outputs.
It also exercises both actual 1GiB total bounds: write to a discard stream, and
read an independently generated hostile stream that exceeds the budget before
opening the oversized entry's sink. No large payload is allocated or retained.
These are host bounds, not Android memory/latency, durability, provider, process
death, Fold, upgrade or release acceptance. Full unchanged host/Android suites
are intentionally outside this isolated preparation target; integration must
perform its own review and required gates.
