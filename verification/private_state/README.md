# Strict portable private-state framing

`PrivateStateCodec` is a pure Task5 prerequisite over new portable records.
It has no runtime callers, filesystem/provider operations, native session JSON
reader, preference edits, migration or import/adoption implementation. Existing
sessionv1/recoveryv2/legacy-pair source is untouched. Do not infer that these native
formats were migrated/tested, or that a successful record validates an archive.

[Reviewed schema](SCHEMA.md) records actual source fields, exact wire framing,
allowlist, limits and future importer responsibilities. One frame contains one
tab, one recovery or one typed preference selection. Document bytes stream into a
**provisional caller sink**; successful return requires strict UTF8, metadata and
cursor ranges, whole-frame SHA256 and trueEOF. Partial or even full sink bytes on
failure are not validated state. The caller owns staging and failed bytes.

URI, baseline, readOnly, clean/dirty and source ID remain named provenance. No
DocumentTab, URI grants or save authority is constructed. Future import must
remap IDs and create dirty drafts with nullURI/unknownbaseline, preserve live
state, enforce12tabs/overflow and staging/graph limits, and handle adoption/replay.
None of those future container or activation guarantees is claimed here.

## Memory and compatibility boundaries

Each call allocates a64KiB transfer array,65540-byte decoder buffer (4bytes for
UTF8 carry),32768-char decode output buffer (64KiB), bounded metadata/strings and
small digest state. Record DTOs contain no payload array/String. Header21bytes +
checksum32bytes leave at most32715metadata bytes within32768total non-payload
bytes; document payload has the existing8,388,608byte bound including BOM.
Preference frames are at most65536bytes. No archive/session-sized buffering,
compression or arbitrary XML parsing exists.

TrueBOMflag requires a prefix and excludes exactly3bytes from text cursor counts.
FalseBOMflag may have literal leadingU+FEFF text because current encodeStrict
allows it. No normalization/trimming/replacement is performed. Metadata limits
can reject oversized native values on future capture; nothing is silently cut.
Source IDs remain inert bounded strings because native session loading accepts
historical IDs beyond generated UUIDs. The framing checksum proves integrity,
not authenticity or authority to adopt imported provenance.

No current history SharedPreferences keys exist in the inspected source, so none
were invented. Existing supported8keys only; custom image settings/bytes, recents,
grants, signing, caches, unuseddark_theme and onboardingsplit_hint_seen are excluded.
The future capture adapter must preserve live excluded settings and report them.

No broad suite, APK/signing, filesystem adoption/restart, SAF/provider, Android,
IME/Fold or physical durability checks ran for this inert codec. M1 remains open.
