# Preview navigation and print readiness implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. This is an investigation and proposed implementation boundary; production changes require the orchestrator's technical review first.

**Goal:** Acknowledge only the currently requested preview DOM, and print the document captured by the print action after its own DOM is ready.

**Architecture:** Keep the bounded LatestPreview renderer, original MarkdownRenderer output API and interactive WebView security configuration. Associate each submitted DOM with a generated identity and validate that identity plus document readiness before acknowledging navigation or applying deferred scroll work. Prefer one separately owned print WebView containing one immutable action capture, so interactive navigation and mode changes cannot replace the document being printed.

**Tech stack:** Existing Java 11-compatible app source, Android minSdk 26 WebView/PrintManager, existing JDK17 host extraction and SDK37 compile tools; no new dependencies.

**Spec:** Existing M0 rendering audit and M2 preview work in `docs/ROADMAP.md`, invariants in `AGENTS.md`, rendering/device gates in `docs/RELEASE_GATES.md`, and the bounded investigation assignment. This plan supplements `verification/preview_behavior/PLAN.md`; it does not reopen queue or renderer implementation.

## Review focus

1. A JavaScript response may arrive after another navigation, edit, tab/theme/font/mode change or shutdown. Validate both the returned DOM identity and the current Java-side epoch again at delivery.
2. An old finish callback may trigger a probe of the genuinely current DOM. Accept that DOM only if its embedded identity and `readyState` match; never infer which navigation generated the callback from its URL or callback order.
3. A timer from an earlier accepted page must not clear newer scroll suppression. Scope flag resets, viewport results and deferred work to their owning page/operation.
4. Printing while the render worker is busy, during tab changes, or with a missing/failing service must not print another document or change editing mode. One immutable print capture and explicit cleanup are required.
5. The print framework may use the WebView adapter after `PrintManager.print` returns. Keep the dedicated WebView alive until the reviewed adapter `onFinish` release boundary; do not destroy it immediately after submitting a job.

## Task 2: One captured, readiness-gated print operation (proposed choice)

**Files:** `MainActivity.java` print action/lifecycle methods and narrow print boundary; `verification/preview_navigation/**`. No renderer, save/history, storage or global UI-layout redesign.

**Interfaces:** Replace fixed350ms action with one main-owned `PrintOperation`: captured source/title/palette/font/BOM policy, request identity and lifecycle state. Proposed entry/cleanup: existing `printDocument()` and `finishPrint(PrintOperation operation, String error)`; cleanup is idempotent and only affects the owning operation. Use the same DOM acknowledgment contract as Task1 on an isolated WebView.

**Alternatives assessed:** Gating the interactive WebView can stop premature printing, but its content may change both before and after adapter creation, including later asynchronous framework layout. Locking that view through printing disrupts navigation/editing and still needs lifecycle ownership. A dedicated one-request WebView avoids temporary Write→Read mutation and preserves Focus/modes. It costs one extra captured source, one render/DOM and a print adapter while a print is active; it is bounded, not free and not an Android peak-memory budget. Do not maintain a queue of print documents.

- [ ] Introduce explicit immutable action capture: capture source/title/theme/font once on main at the print action, render off main on the existing serial renderer executor with at most one outstanding print task. Use a dedicated bounded callback/operation identity; interactive LatestPreview remains independently bounded. A second print action while active is rejected with a concise status, never enqueued. Logical cancellation/timeout must NOT release the physical render admission slot: MarkdownRenderer is non-interruptible. Keep that slot until its task actually exits, or until removal of a not-yet-running task is positively established. Repeated cancel/timeout/retry cannot capture or enqueue additional print documents behind it. Check admission before copying editor text.
- [ ] Decide and test an explicit print capture input bound: proposed existing `DocumentIO.MAX_DOCUMENT_BYTES`8,388,608 strict UTF-8 bytes including3BOM bytes when the captured document policy has BOM. Reject excessive UTF-16 length before copying; validate/count the immutable capture with bounded encoding buffers before rendering, rejecting malformed surrogates and exact-cap+1. This guard is NEW for printing (baseline print has no explicit size/strictness check), and root accepted it as an explicit new guard; do not describe it as preserved behavior. No newline/content normalization; BOM accounting does not insert a visible BOM into rendered content. Task count/input cap does not establish an HTML/DOM or Android peak-memory bound.
- [ ] Create one print WebView on main with the identical existing security settings and original base URL. Load only the captured renderer output plus nonvisual DOM identity. No editor mode/rebuild mutation and no remote resources. Its WebViewClient consumes all navigation; it never calls interactive handlePreviewUri, jumps editor offsets, changes mode, or starts external intents. PDF link markup/base URL remain unchanged, and the interactive link handler itself stays byte-equivalent. Need real Android validation that the offscreen print WebView lays out correctly.
- [ ] Submit an adapter only after current print DOM readiness acknowledgment, only once and only while Activity/operation remains live. Capture title at action time. Use a lifecycle-only PrintDocumentAdapter wrapper forwarding the original layout/write arguments unchanged, including CancellationSignal, framework callbacks, PageRange array and ParcelFileDescriptor. Do not close the framework descriptor, replace cancellation listeners, or take ownership of result callbacks. SDK37 `javap` confirms LayoutResultCallback/WriteResultCallback constructors are package-private, so an app cannot implement callback subclasses to count delegated asynchronous completion; do not create host-only public constructors that hide this constraint. `onStart` forwards at most once, `onFinish` forwards at most once. After retirement begins, late layout/write requests are answered via the original callback's cancellation method without reaching the delegate. Source/API review must settle the safe release boundary below before this wrapper is implemented.

Mark SUBMITTING before invoking PrintManager because framework callbacks can race its return; never assume a thrown exception/null job implies no delegation occurred. Invalidate own pending callbacks and cancel a known job once; neither cancellation nor Activity destruction is proof that delegated layout/write finished. Before any adapter exposure, WebView disposal on main is safe after logical cancellation; after exposure use the reviewed quiescence boundary below. ### Reviewed print framework lifecycle boundary (Task2 still not implemented)

Root inspected the canonical Android API documentation on2026-10-15: [`PrintDocumentAdapter.onFinish()`](https://developer.android.com/reference/android/print/PrintDocumentAdapter#onFinish()) is called when printing finishes and permits releasing resources on the main thread. [`onLayout`](https://developer.android.com/reference/android/print/PrintDocumentAdapter#onLayout(android.print.PrintAttributes,android.print.PrintAttributes,android.os.CancellationSignal,android.print.PrintDocumentAdapter.LayoutResultCallback,android.os.Bundle)) and [`onWrite`](https://developer.android.com/reference/android/print/PrintDocumentAdapter#onWrite(android.print.PageRange[],android.os.ParcelFileDescriptor,android.os.CancellationSignal,android.print.PrintDocumentAdapter.WriteResultCallback)) specify that no further adapter calls occur until the supplied result callback completes. This documented framework lifecycle, after successful forwarding of delegate `onFinish`, is the approved disposal boundary; it is NOT an inference from generic I/O cancellation, Activity destruction or job status. Package-private callback constructors require forwarding the actual framework callbacks unchanged, not app callback subclasses.

Use one process-wide static print admission owner, managed on main with identity-checked transitions, covering capture/render/load/submitted adapter ownership. An Activity recreation cannot admit another print while the prior owner remains. Cancellation/destroy stops new delegate calls and requests known-job cancellation, but does not dispose an exposed view. Missing or throwing delegate `onFinish` conservatively retains the bounded owner/view; do not promise unconditional cleanup. A successful forwarded `onFinish` disposes on main and releases only its own slot, subject also to actual physical-render completion. Test synchronous/reentrant `onFinish` inside PrintManager.print before it returns (including subsequent null return or throw); stale return/finally work cannot resurrect the finished operation or clear a newer global owner. Before exposure, cancellation may dispose the view, but non-interruptible render admission persists until actual worker exit. Worker-exit/admission handoff cannot depend solely on an Activity Handler callback that `onDestroy.removeCallbacksAndMessages` may discard; use process-owned bookkeeping with a surviving delivery path and identity check. Physical and logical ownership are separate throughout.
